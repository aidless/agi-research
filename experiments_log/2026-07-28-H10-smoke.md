## 1. What this log is for

This log records the smoke-test result for the Project G
architecture (LLMSlotMonitor). It is NOT the H10 pre-registered
experiment; the real H10 experiment uses frozen-LLM rollouts and
is defined in `2026-07-28-PRE-REGISTERED-H10.md`.

The smoke test answers one question: **does the architecture work
end-to-end on a known synthetic signal?** If yes, the architecture
is ready for the real experiment. If no, there is a bug.

## 2. Setup

- Synthetic data: 200 traces, 50% failure, 50% success.
- Failure signal: lower logit variance in last 5 positions
  (mimics a model losing confidence near the end of a wrong
  answer).
- Train: 160 traces, 50 epochs, Adam lr=1e-3, BCE loss.
- Eval: 40 held-out traces.
- Seed: 42.
- Compute: ~10 seconds on CPU.

## 4. Final result

- **Final AUROC: 0.848**
- **Final accuracy: 0.875**

(Epoch 50 numbers; peak at epoch 20 was 0.929.)

## 5. Verdict

**Architecture validates** on the synthetic signal. AUROC is well
above random (0.5) and well below the "suspiciously high" threshold
(0.95). The LLMSlotMonitor can pick up the synthetic failure
signal end-to-end.

## 6. What this does NOT show

- It does NOT validate the real H10 hypothesis (decoupled > joint
  on LLM traces). The smoke test has no "joint Monitor" arm.
- It does NOT validate the failure-label definition. The synthetic
  signal is generated, not derived from a real LLM.
- It does NOT validate the rollout collector at scale. The smoke
  test uses 200 traces; the real H10 may use 1000+.

## 7. Next step

If the user wants to run the real H10:
1. Choose a frozen LLM (Qwen-1.5B, Phi-3-mini, or other small LM).
2. Choose a reasoning dataset (GSM8K, MATH, or other).
3. Confirm compute budget (CPU may be too slow; GPU preferred).
4. Run the real experiment per pre-registered design.

Until then, this smoke test log is the only Project G evidence.
