# Q-BoN + CQL (Conservative Q-Learning) — partial fix for OOD overestimation

> Date: 2026-07-26
> Status: PARTIAL — seed 0 positive, seed 1 negative but small magnitude
> Author: 刘泽文 (Liu Zewen) + Codex

## 1. Motivation

v5 Q-BoN failed because Q-function overestimated OOD (state, action)
combinations. CQL (Kumar et al. 2020) is the standard offline RL
fix: add a regularization term that penalizes Q-values uniformly
across all actions, then subtract Q on data actions.

L_CQL = logsumexp_a Q(s, a) - Q(s, a_data)
L_total = TD_loss + alpha * L_CQL

## 2. Implementation

Modified `code/q_bon.py`:
- Added `--cql-alpha` CLI arg (default 1.0)
- Modified `train_q_network` to add CQL penalty when alpha > 0

## 4. Analysis

**CQL works**: Q values dropped from 170-180 to 40-90 range. The
logsumexp penalty pulls down Q for all actions; subtracting Q on data
actions prevents collapse to zero.

**Still not robust across seeds**:
- seed 0: +16.2 (POSITIVE, but partly because PPO was very bad)
- seed 1: -10.5 (NEGATIVE, but small magnitude)

**Honest reading**: CQL makes things less bad (delta magnitude from
-198 to -10/+16). But the gain depends heavily on PPO baseline quality.
Both seeds had PPO performing poorly (0.2 and -13.1), which suggests
the 100K PPO budget on this env with these seeds just isn't reliable.

## 5. Why CQL partially fixes and what's still missing

CQL addresses:
- ✓ Q overestimation on OOD actions (Q values dropped 5x)
- ✓ argmax always being the same action (now varies across seeds)
- ✓ catastrophic BoN failure (delta from -198 to -10)

Still missing:
- ✗ PPO baseline reliability (still poor on these seeds)
- ✗ Q ranking accuracy (still picks suboptimal actions)
- ✗ Cross-env validation (need more envs)
- ✗ alpha tuning (1.0 may not be optimal)

## 6. Y1 follow-up

CQL alpha tuning (try 0.1, 0.5, 1.0, 5.0):
- Larger alpha = more conservative Q = less OOD action use
- Smaller alpha = more aggressive Q = riskier but possibly better
  in-distribution performance

Combine with:
- Action masking (only consider PPO top-K actions)
- Larger Q network (128 or 256 hidden)
- Ensemble of Q networks

## 7. Conclusion

CQL is the **right direction** for Q-BoN. It fixes the worst failure
mode (OOD overestimation) and brings delta magnitude to acceptable
levels. But it does not produce a robust TTC win on LunarLander-v3
with 100K PPO budget on seeds 0-1.

Y1 work should focus on:
1. Alpha tuning + larger Q-network
2. Cross-env validation (Procgen if installable)
3. Combined CQL + action masking
4. PPO baseline stability improvements
