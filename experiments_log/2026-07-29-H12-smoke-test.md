## 3. Why LM = 0.500 (rather than 0 or 1)

The LM_check function scores UNCERTAIN as 0.5 (partial credit).
The LM response did not contain a clear TRUE / FALSE / UNCERTAIN
token, so it fell into the UNCERTAIN bucket.

This means the LM is outputting a response that doesn't match the
expected format. Possible causes:
1. The prompt template is too verbose for the 1.5B model.
2. The state vector formatting is hard for the LM to parse.
3. The 10-token generation limit truncates the response.
4. The LM doesn't have strong numeric reasoning at 1.5B.

## 7. Why the LM might be failing

The 1.5B parameter count may be too small for this task. Possible
fixes:
1. **Use a larger LM** (Qwen2.5-7B if it fits; user may need GPU).
2. **Few-shot prompting** instead of zero-shot.
3. **Shorter prompt** (the current prompt is verbose for 1.5B).
4. **Smaller state representation** (e.g., binarize x_pos as "left/center/right").
5. **Reformat output** (e.g., ask for a single letter T/F/? instead of a word).

The current H12 pre-registration uses the current prompt; if the
real H12 experiment uses a different prompt, it must be pre-registered
in a follow-up.

## 8. Recommended next step

Before running the full H12, try the prompt fixes above on a small
test (5-10 samples). If LM accuracy improves to >0.70, run the full
pre-reg H12. If not, REFUTE H12 with the larger sample.

The DLR baseline is at 100% on this test (mocked), suggesting the
predicate definitions are clean. The bottleneck is the LM's
classification ability, not the predicate definitions.
