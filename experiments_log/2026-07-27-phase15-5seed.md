## 3. Statistical significance

Welch-style t-test (paired not assumed; n=5, df=4):
\\\
t = delta_avg / (delta_std / sqrt(n))
  = 21.5 / (67.1 / sqrt(5))
  = 21.5 / 30.0
  = 0.72
\\\

For df=4, two-sided p<0.05 requires |t|>2.78. We are well below.
**Conclusion**: with n=5 seeds we cannot reject H0 (delta=0).

## 4. Honest interpretation

### 4.1 What the result does say
- **Direction is positive**: 3/5 seeds improve, mean delta = +21.5.
- **Architecture does not break**: every seed ran to completion, no
  crashes, all 4 layers produced output, SlotMonitor AUROC ~0.989.

### 4.2 What the result does NOT say
- **NOT a publishable H1 yet**: p>0.05, no significance.
- **NOT robust to seed**: seed variance is larger than effect size.

### 4.3 Why variance is so high
- **PPO convergence varies wildly**: seed 2 PPO got ungated_mean=11.4
  (PPO learned almost nothing useful), seed 4 got -5.1. The Monitor
  fires when PPO is bad, but the Q-function then picks bad actions
  (CQL with 200-episode training set has limited coverage).
- **avg_gates ranges from 0.4 to 287.2**: the Monitor threshold is
  0.5 in all cases, but the underlying failure-probability distribution
  differs across seeds because PPO rollouts differ. Seed 3 had 287
  gates per ep (almost every step gated) and got delta=-45.
- **Per-episode variance is huge**: each eval episode has +/-100
  noise on LunarLander-v3, so 5 episodes per seed averages are noisy.

## 5. Failure mode taxonomy

| Seed | avg_gates | delta | Pattern |
|------|-----------|-------|---------|
| 0    | 0.4       | +54.5 | Monitor rarely fires; gating has no effect |
| 1    | 10.2      | -55.1 | Monitor fires sparsely; Q picks bad actions |
| 2    | 22.0      | +91.6 | Monitor fires moderately; Q happens to help |
| 3    | 287.2     | -45.4 | Monitor fires on every step; Q destroys PPO |
| 4    | 57.6      | +62.2 | Monitor fires moderately; Q helps |

**Delta is determined by Q quality, not by Monitor frequency.** When
Q is well-calibrated (seeds 0, 2, 4), gating helps. When Q is
miscalibrated (seeds 1, 3), gating hurts regardless of how often the
Monitor fires.

## 7. Implications for Phase 2

### 7.1 The CQL coverage problem
With only 200 training episodes, Q's coverage of (state, action) space
is thin. CQL penalizes OOD actions but cannot fix the underlying
data sparsity. Better Q training requires:
- More PPO rollouts (e.g., 1000+ train episodes)
- Or: use a single shared Q value (not per-action), reducing the
  effective dimensionality.
- Or: skip Q entirely when Monitor fires; use a fallback heuristic
  (e.g., no-op / center thrust).

### 7.2 Monitor calibration
The Monitor's failure-probability distribution varies hugely across
seeds because the underlying PPO behavior varies. **Platt scaling on a
held-out validation set** would normalize the threshold. Without
calibration, the 0.5 threshold is essentially random.

### 7.3 Sample size
For a proper H1 with delta=20, std=67, we need:
\\\
n = (z * sigma / delta)^2 = (2 * 67 / 20)^2 = 45 seeds
\\\
So roughly **45 seeds** to detect delta=20 with 80% power at p<0.05.
Alternatively, increase n_eval_episodes from 5 to 50+ per seed, which
shrinks per-seed variance by sqrt(10).

### 7.4 Recommended next steps (DEC-0011 v0.2)
1. **Bump n_eval_episodes to 50** for future sweeps; cost is 7min -> 70min
   per seed but variance reduces 3x.
2. **Add Q coverage guard**: refuse to gate if Q has seen <50 (s,a) pairs
   in training.
3. **Platt-scale the Monitor**: train a 1-param logistic on a held-out
   set; pick threshold to match a target FPR (e.g., 10%).
4. **Re-run 5-seed sweep** after (1)+(2)+(3); expect t > 2 and
   delta_avg to converge.
