# Q-BoN TTC (Y1 seed for ADR 0011 alternative)

> Date: 2026-07-26
> Status: Q-function trains but BoN fails due to over-estimation
> Author: 刘泽文 (Liu Zewen) + Codex

## 1. Motivation

After 4 failed Monitor-BoN attempts (v1-v4), try Q-function BoN as
alternative. Q-function predicts expected return (continuous) which
is the right reward signal for TTC, unlike failure probability
(binary).

## 2. Method

`code/q_bon.py` (10230 bytes):

1. Train PPO on LunarLander-v3 for 100K steps
2. Collect 200 frozen rollouts (84375 (s, a, r, s') tuples)
3. Train Q(s, a) via TD(0): target = r + gamma * max_a' Q(s', a')
4. Eval vanilla PPO: 30 episodes, standard sampling
5. Eval Q-BoN: 30 episodes, at each step sample N=4 candidates from PPO,
   pick argmax_Q(s, a)

Q-network: input [state, action_onehot] (8+4=12), 2 hidden layers
64 each, ReLU, output scalar Q.

## 3. Results (LunarLander-v3, 100K PPO, N=4, seed 0)

| metric | value |
|---|---|
| Q training final loss | 23.66 (still high — Q values ~170) |
| Sample Q range | 169-180 across actions |
| **argmax action (all 8 sample states)** | **action 2 (main engine)** |
| Vanilla PPO mean | 162.7 +/- 96.3 |
| Q-BoN mean | -36.2 +/- 68.8 |
| **Delta** | **-198.9** |
| Action distribution (eval) | {0: 646, 1: 2687, 2: 7980, 3: 2726} |

Q-BoN picks action 2 (main engine) 57% of the time. Overuse leads
to fuel exhaustion and crash.

## 4. Diagnosis: Q-function overestimation

The Q-function learned correct Q-values (~170-180) for states where
PPO had been, but **overestimates Q for OOD (state, action) combinations**.

In offline RL, this is the classic "extrapolation error":
- Q(s, action=2) is high when PPO used action 2 appropriately
- Q(s, action=0) is high when PPO didn't use action 0 much in training
- BoN picks argmax = action 2 every time
- Eval fails because BoN doesn't use fuel conservatively

This is the **distribution shift** problem in offline RL.

## 5. Why Monitor-BoN failed vs Q-BoN failed differently

| failure mode | Monitor-BoN | Q-BoN |
|---|---|---|
| signal | "failure prob" (binary) | expected return (continuous) |
| ranking metric | lowest failure prob | highest Q |
| actual problem | "low failure" ≠ "high return" | OOD extrapolation |
| solution | use Q instead of Monitor (we tried) | use conservative Q-learning |

Q-BoN is **closer to correct** than Monitor-BoN (uses right reward
signal), but inherits the fundamental offline RL problem.

## 6. Y1 fixes for Q-BoN

Standard offline RL techniques that would help:
1. **Conservative Q-Learning (CQL)**: penalize Q-values for OOD actions
2. **Ensemble of Q networks**: use disagreement as uncertainty signal
3. **Action masking**: only consider actions PPO would take (top-K by PPO prob)
4. **BCQ (Batch-Constrained Q)**: perturb actions toward in-distribution
5. **IQL (Implicit Q-Learning)**: use expectile regression instead of TD

## 7. Conclusion

Q-BoN is a **better direction than Monitor-BoN** (correct reward signal)
but still fails due to offline RL distribution shift. Y1 should
implement CQL or IQL on top of this Q-BoN infrastructure.

**Infrastructure reusable**: state cloning + Q network + BoN ranking
is now in place. Y1 work just needs better Q-learning algorithm.
