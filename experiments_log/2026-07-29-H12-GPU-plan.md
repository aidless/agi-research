## 1. Why larger LM for H12

### 1.1 H12 smoke test result (n=1)

- Qwen2.5-1.5B-Instruct + simple arithmetic:
  - LM accuracy: 0.500 (= Random)
  - DLR baseline: 1.000 (mocked at 95.5% LunarLander accuracy)
  - Random baseline: 0.500

The LM failed to parse the expected output format (TRUE / FALSE /
UNCERTAIN). The 1.5B model may be too small for this classification
task.

### 1.2 Why larger LM may help

- **Better instruction following**: 7B+ models are better at parsing
  structured output formats.
- **Better numeric reasoning**: 7B+ models can do basic arithmetic
  more reliably than 1.5B.
- **Kimi K3 suggests scale helps structured reasoning**: Kimi K3
  (2.8T) excels at structured reasoning tasks. While we can't
  reproduce 2.8T, even 7B may be enough for the H12 task.

### 1.3 Alternatives to scaling LM

- **Better prompt engineering**: few-shot examples, clearer output
  format. Cheaper than scaling LM.
- **Fine-tuning the LM**: train the 1.5B on the predicate task.
  Requires labeled data; risks overfitting.
- **Use the DLR as the LM's teacher**: the DLR's classification
  can be used as training data for the LM. Combines DLR's
  in-domain knowledge with LM's general reasoning.

We recommend trying the prompt engineering first (cheapest, fastest),
then larger LM if needed.

## 2. Pre-registered hypothesis: H12b

**H12b**: A larger LM (Qwen2.5-7B-Instruct) achieves higher
predicate-classification accuracy than Qwen2.5-1.5B-Instruct on
the H12 task, on the same synthetic arithmetic state-predicate
dataset.

**Decision rule** (pre-registered before any data collection):
- VALIDATED if Qwen2.5-7B accuracy > Qwen2.5-1.5B accuracy by
  delta > 0.15 AND Qwen2.5-7B accuracy >= 0.70 (passes the H12
  threshold).
- REFUTED if Qwen2.5-7B accuracy < Qwen2.5-1.5B accuracy.
- INCONCLUSIVE otherwise.

**Pre-registered sample size**: n=5 seeds, 50 (state, predicate)
pairs per seed. Total: 250 evaluations per arm.

**Pre-registered compute**:
- Qwen2.5-7B float16 on A100 / H100: ~30 min for 50 traces x 5 seeds.
- Plus Monitor training + evaluation: ~10 min.
- Total pilot: ~1 hour on GPU. (vs ~5+ hours on CPU for the same.)

## 3. Pre-registered hypothesis: H12c (alternative: prompt engineering)

**H12c**: A few-shot prompt with 3 worked examples achieves higher

in Qwen2.5-1.5B-Instruct, on the same H12 task.

**Decision rule**:
- VALIDATED if few-shot accuracy > zero-shot accuracy by delta > 0.15
  AND few-shot accuracy >= 0.70.
- REFUTED otherwise.

**Pre-registered sample size**: same as H12b (n=5 seeds, 50 pairs).

**Pre-registered compute**: same as H12 smoke test (~30 min on CPU).
Cheaper than H12b.

## 4. Implementation outline

### 4.1 H12b (larger LM)

```python
def load_lm(model_path="Qwen/Qwen2.5-7B-Instruct", device="cuda",
           dtype=torch.bfloat16):  # use bf16 for A100/H100
    from transformers import AutoModelForCausalLM, AutoTokenizer
    tokenizer = AutoTokenizer.from_pretrained(model_path)
    model = AutoModelForCausalLM.from_pretrained(
        model_path, dtype=dtype,
        low_cpu_mem_usage=True,
        device_map=device,  # auto-distribute across GPUs
    )
    model.eval()
    return model, tokenizer
```

Note: bf16 (not float32) is fine on A100/H100; it's the standard
quantization. ~14 GB VRAM for 7B model.

### 4.2 H12c (few-shot prompt)

```python
FEW_SHOT_PROMPT = """You are a type checker for a robotics system.
Determine whether the predicate holds for the given state.

Example 1:
State: [x_pos=0.0, y_pos=0.5, x_vel=0.0, y_vel=-0.5, angle=0.0, ang_vel=0.0, leg_l=1.0, leg_r=1.0]

Answer: FALSE (y_pos=0.5 is not near ground)

Example 2:
State: [x_pos=0.0, y_pos=0.1, x_vel=0.0, y_vel=0.0, angle=0.0, ang_vel=0.0, leg_l=1.0, leg_r=1.0]
Predicate: "near_ground"
Answer: TRUE (y_pos=0.1 is near ground)

Example 3:
State: [x_pos=0.0, y_pos=0.5, x_vel=0.0, y_vel=0.0, angle=0.2, ang_vel=0.0, leg_l=1.0, leg_r=1.0]
Predicate: "upright"
Answer: FALSE (angle=0.2 is not upright)

Now determine:
State: {state}
Predicate: "{predicate}"
Answer: """
```

Few-shot prompting is well-known to improve LM classification on
structured tasks; H12c tests this on the H12 task.

## 5. Risks and honest framing

### 5.1 Risks
- **GPU availability**: We currently have no GPU. This plan is
  contingent on obtaining GPU access (HF Residency, Lambda Labs,
  or in-kind donation).
- **Compute budget**: even on GPU, 7B is 5x the cost of 1.5B.
  Total pilot ~1 hour; full pre-reg H12 (n=5 x 200 rollouts/seed)
  ~5 hours.
- **Diminishing returns**: 7B may not be enough. The path to
  frontier-level H12 may require 70B+, which is out of our reach.
- **LM may still fail even at 7B**: if the failure is in the prompt
  or the task definition, scaling the LM doesn't help. H12c
  (prompt engineering) is the cheaper alternative.

### 5.2 Honest framing
- H12b and H12c are pre-registered hypotheses, not claims.
- The current H12 smoke test (LM = Random at 1.5B) is a real
  negative result. The plan is to test whether larger LM or
  better prompting fixes it.
- If both H12b and H12c fail, H12 is **REFUTED at our scale**;
  pivot to a different Project D direction.
